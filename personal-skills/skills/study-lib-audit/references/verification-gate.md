# 结论与证据对应检查

在准备报告成功、提交或合并时使用。先写清具体结论，再选择能够支持它的证据；不要先拿到一个成功退出码，再扩大它的含义。

## 逐项对应

| 拟报告的结论 | 至少需要的证据 | 不能替代的东西 |
|---|---|---|
| 已修复原问题 | 原失败输入在旧版触发问题、在修复版不再触发；最小用例及原始完整场景的行为结果 | 代码改了、单次测试恰好通过、只修好缩小后的输入 |
| 检查器能拦截该错误 | 已知错误输入被拒绝，退出码与原因符合规则 | 只有合法输入通过 |
| 本次测试通过 | 对应版本的命令、实际日志、退出码、失败和跳过数 | 旧提交绿色标记、未读的代理总结 |
| 某题已核实 | 实际读取的完整题面、图形与对应答案，来源版本及定位 | URL 字段合格、答案字母、转载网站数量 |
| Word/PDF 已同步 | 内容比对与实际渲染检查范围 | 文件存在、能打开、构建器退出 0 |
| 已写回主分支 | 远端 PR 合并状态、主分支提交和内容树核对 | 本地 commit 成功、PR 已创建 |

## 控制重复检查的成本

- 记录证据对应的提交 SHA；未提交文件可记录关键文件指纹或清晰的差异范围。记录环境、命令、退出码和已读日志。
- 如果相关文件、输入及环境没有变化，可明确引用本会话中已读的运行结果，无须每发一条消息重跑全套。提交前的测试仍需覆盖实际待提交内容。
- 若代码、配置、依赖或来源内容发生变化，重跑受影响检查；必须满足仓库 CI 门禁。仅局部通过就报告局部，不扩大到全套。
- 截断日志不足以判断全套结果时，补取最终汇总和相关失败上下文；网络请求失败时保留失败事实。

## 安全复现与检查器校准

- 用临时合成输入或隔离工作区分别运行旧版和修复版。保留失败前提与新旧结果；不要在共享脏工作区执行 reset、checkout 或 restore 来“回滚验证”。
- 对新检查规则至少覆盖一个会被错误放行的输入和一个合法输入。优先复用已存在的回归用例，避免重复造测试框架。
- 核查测试预期值的来源。实现和测试调用同一计算逻辑或读取同一错误标签，即使一致也无法排除共同错误；使用独立规范、已读题面或手工推导。
- 例：缺少答案定位的记录不能计入已核实；合法 Markdown 空格变化不能使题目静默消失；显式根目录无效时不能自动选择别的库。
- 这些例子说明如何选择测试，不能写死整库当前题数。固定数量只在某份明确快照的完整性回归中使用，并在合法新增记录时审查更新。

## 阅读与计算的边界

- 对数学答案独立推导或举反例，并核对题目条件。数值复算不能替代原卷版本鉴定。
- 对统计明确候选集合、实际核验范围、分值归属和去重规则。定向核验不能给出随机抽样的准确率。
- 对来源相互转载的页面，不以“多个网站一致”推断来源独立或官方确认。
- 测试 Skill 时核对实际工具结果与改动，而不只信代理说“成功”。少量试用仅支持对应场景，不声称已经证明全面可靠或节省某个百分比时间。

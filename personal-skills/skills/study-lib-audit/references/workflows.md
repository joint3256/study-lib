# 检查命令与证据规则

先验证目标仓库确有这些文件，并审阅其当前参数与行为；脚本缺失时报告位置，不伪造执行结果。以下命令均从已验证的仓库根目录运行。不要硬编码某次云端工作目录。

## 路径与库内链接

```text
python -B 技能/cz-combine/scripts/check_library.py
python -B scripts/check_repository_links.py
```

- 路径配置优先级和发现规则以当前 `技能/cz-combine/references/知识库检索.md`、`技能/cz-combine/scripts/check_library.py` 为准。
- 显式根目录使用 `--lib-root` 或 `CZ_COMBINE_LIB_ROOT`；本地教材目录使用 `--textbook-root` 或 `CZ_COMBINE_TEXTBOOK_ROOT`。无效显式配置不得回退。
- 在实际运行技能的进程中核对环境变量；终端里设置不代表桌面应用已读取。Windows 示例路径只作本机配置，不写回公共规范。
- 检查具体教材时用 `--textbook "相对路径.docx"`，检查所需库内文件用 `--require "相对路径.md"`。一般目录检查成功不等于教材已安装或教材内容已读取。
- 链接检查仅验证其实现覆盖的本地文件目标与索引；不保证外部网址、锚点及知识事实。

## 真题证据

```text
python -B scripts/check_exam_evidence.py
```

默认读取当前仓库 `真题考点/天津`；指定其他资料目录时传入一个明确目录参数。保持各年份题号和七列结构，不静默吞掉异常行。理解脚本的年份范围和来源类别，不擅自把不支持的数据丢弃。

每条“已核实”的证据采用四部分，中文分号分隔：

```text
题面 https://example.org/paper 第3图 第14题；答案 https://example.org/answer 第8图 第14题；来源 第三方解析版；核验 YYYY-MM-DD
```

这是格式示例，不能直接当证据；替换为实际读取的网址、定位和核验日期。

- 题面和答案分别定位，允许同 URL 的不同页或图；两者必须对应本条题号。
- 区分 `官方原卷`、`第三方原卷转载`、`第三方解析版`。扫描卷带机构水印不等于本次从官方取得。
- 图号说明是页面预览顺序还是印刷页码；必要时记录已读取文件的哈希，哈希只能核对文件一致性。
- 核验日期不能在未来，也不能早于考试年份。若执行环境日期异常，先核实实际日期，不篡改日期来过检。
- 原始考点文本分组计数不等于统一考点频率。先统一标签和统计范围，再区分“出现年份数”和“题目次数”；分值必须按小问去重。
- 使用脚本最新输出计算进度；不在 Skill 固化某批题数、百分比或测试总数。

### 整卷核验与考点归属

- 先列出题面、续页、附图和答案的对应关系；同时记录网页图序与印刷页码。整卷完成须覆盖实际题号集合，不能以读到最后一页代替逐题覆盖。
- 对选择题先读清“正确/错误”“符合/不符合”等问法，再核对所有选项及答案。考点标签必须说明实际考查内容，不能把干扰项的情境误当正确答案；多选题逐项核对。
- 对实验和综合题列全小问及控制条件，再归纳考点。比较变量、控制变量和结论适用条件不能互换；后面的小问可能引入新的变量。
- 对计算题按题面条件独立推导，保留单位、符号定义和图线的有效区间。参考答案与独立结果不一致时先查版本、图形和条件，不为凑一致而改数据。
- 只有部分题目完成时逐条标记，保留其余待核实。来源类型按实际获取渠道记录；转载页声称“来源官方”不改变本次获取渠道。

## 按风险选择回归

```text
python -B -m unittest discover -s tests -p test_cz_combine_paths.py -v
python -B -m unittest discover -s tests -p test_tiqu_reliability.py -v
python -B -m unittest discover -s tests -p test_math_and_exam_evidence.py -v
python -B -m unittest discover -s tests -p test_repository_portability.py -v
```

按改动选择：路径检查；提取与输出保护；数学、证据及 Word 一致性；链接索引及可移植性。仓库 CI 或跨组件修改需要全量时用：

```text
python -B -m unittest discover -s tests -v
```

保留运行日志中的失败、跳过及原因。Windows 未安装转换程序时，不能把转换测试跳过说成转换已验证；可明确补充 Linux 的实际运行证据。

- 最小复现应保留与故障有关的工作目录、编码、换行和路径条件。断言用户遇到的具体错误输出、退出码或遗漏记录，而非仅断言“不崩溃”。
- 用最小输入定位并修复后，再运行原始完整输入和入口；原场景不可用时明确尚未验证该场景，不扩大局部通过的结论。
- 真题测试的预期值取自实际读取的原卷及独立推导；源记录与 Word 一致只能证明同步，另须核对事实和渲染成品。不要调用被测逻辑生成它自己的预期值。

## 提取与 Word

- 提取工作流先读当前 `技能/tiqu-extractor/SKILL.md`。复用 `verify_extract.py`、`verify_docx.py`；不只检查文件能否打开。
- 具体参数先从脚本源码或其支持的 `--help` 核对，不对未知接口盲跑。
- 输出保护在临时目录内用合成素材验证；不得用用户既有输出测试删除行为。
- `scripts/build_tianjin_docs.py` 会重写生成文档，不是只读检查。仅在相应源文件确需同步且已有修改授权时运行；核对生成文件差异，不提交无关重生成。
- 同步题号、题型、分值、状态及来源；逐页检查表格、公式和图形。缺少字体或转换程序时报告实际限制，不冒充视觉检查完成。
- 只生成受本批次影响的文档；需要时用前后文件指纹确认无关文档未被重写。使用文档技能的既有渲染器，先核对中文和数学符号能显示，再检查全部实际输出页面；不以 DOCX 的缓存页数代替渲染页数。

## GitHub 提交

使用连接器的等价操作或已认证 CLI。不要索取或输出令牌。已有权限仍以实际仓库访问结果为准。

提交前至少读取：

```text
git status --short
git diff --stat
git diff --check
git diff --name-status
```

检查新文件和暂存区后，显式暂存本任务路径。以实际 PR 提交的 CI 为准；检查完成不代表所有知识已正确。检查日志解释失败；复核远端头后按授权合并，最后验证主分支和 PR 已合并状态。
